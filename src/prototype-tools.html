Agent 工具循环：7 个工具 + 分页读文件

要回答的问题：把 CLI 从"一次对话"升级成"会用工具的 agent"时，这套循环逻辑和这 7 个工具的契约对不对？ 循环是：模型返回 tool_use → CLI 执行工具 → 结果回喂给模型 → 直到模型给出最终文本。 模拟器里有一个虚拟文件系统和一个"模拟模型"——你扮演模型决定它下一步请求哪个工具，观察循环怎么推进、怎么处理错误、怎么被截断。

设计约定（要验证的）：① 工具执行出错时，错误作为 tool_result 回喂给模型（让它自己恢复），而不是让 CLI 崩溃；② 迭代上限（默认 10 次）防止模型无限调工具；③ 工具结果上限 8000 字符，超出截断并标记；④ read_file 分页：用 offset/maxLines 控制每次读取长度，剩余内容用 [TRUNCATED] 标记提示下一段从哪里读；⑤ 归一化的 tool_use/tool_result 隐藏两家提供方的协议差异（DeepSeek 的 tool_calls ↔ Claude 的 tool_use——由适配层负责翻译）。
开放决策：bash 工具的沙箱策略（模拟器里 rm -rf 会被拒绝，真实 CLI 要不要 allowlist / 确认？）。
